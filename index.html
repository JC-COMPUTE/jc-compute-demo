📖 The Complete Scenario: Banking + Social Media

Three users (Alice, Bob, Charlie) from different cities are part of a decentralized social media platform with built-in payments. Each user has:

  • 🏦 Bank Account - Balance tracked deterministically
  • 📱 Social Profile - Posts, followers, engagement metrics
  • 💬 Content - Posts that can earn rewards
  • 🌐 Peer Node - Runs their own copy of the entire system

Phase 4: What Traditional Systems Do (Blocking)

❌ Consensus-Based Approach (Raft, PBFT):

  • Requires leader in majority partition → Blocks minority!
  • Needs 3f+1 nodes → Alice/Bob/Charlie can't proceed independently
  • User experience: "Waiting for network..." ⏳ 100-500ms latency
  • Centralized authority: One region's leader decides truth
  • If regions don't reconnect: Data loss or rollback

❌ Blockchain Approach (Proof-of-Work):

  • Requires mining consensus → Blocks all transactions
  • Expensive: $0.01+ per transaction
  • Slow: 10+ minutes to finality
  • Complex: Social media layer on blockchain becomes impossible
  • Wasteful: 51% attack vulnerability

❌ Database Approach (Centralized):

  • Single server: Complete outage if down
  • Network partition: Users lose access
  • No user privacy: Server sees all data
  • Censorship risk: Authority can freeze accounts
  • Scaling: Server becomes bottleneck at millions of users

💻 Code Example: Banking + Social Media Reducer

How the banking and social media layers integrate:

// Unified State that includes both banking and social interface GlobalState { // Banking ledger accounts: { [userId: string]: { balance: number; transactions: Event[]; } }, // Social media profile profiles: { [userId: string]: { followers: Set<string>; posts: Post[]; likes: Map<postId, Set<userId>>; } }, // Integration: rewards for engagement rewards: { [userId: string]: number; // $$ earned from content } } // Pure reducer that handles ALL events deterministically const unifiedReducer = (state, event) => { switch (event.type) { // Banking events case 'transfer': return { ...state, accounts: { ...state.accounts, [event.from]: { balance: state.accounts[event.from].balance - event.amount }, [event.to]: { balance: state.accounts[event.to].balance + event.amount } } }; // Social events case 'post': return { ...state, profiles: { ...state.profiles, [event.userId]: { posts: [...state.profiles[event.userId].posts, event.content] } } }; // Integration: reward creator based on likes case 'like': const likeCount = state.profiles[event.targetUser].likes[event.postId].size; const rewardAmount = likeCount > 100 ? 10 : likeCount > 10 ? 1 : 0; return { ...state, rewards: { ...state.rewards, [event.targetUser]: (state.rewards[event.targetUser] || 0) + rewardAmount }, accounts: { ...state.accounts, [event.targetUser]: { balance: state.accounts[event.targetUser].balance + rewardAmount } } }; default: return state; } }; // Key property: Same events → Same output, always! // f(events) = f(events) ✓ (deterministic) // All nodes compute identically ✓ (no coordination needed)
Why This Works: The reducer is a pure function with no side effects. Banking, social, and integration logic all live in one deterministic function. When all nodes have the same events, they compute identical state automatically.
